What problem does it solve?

Skills fail in predictable places: the description that reads like a store blurb instead of a trigger, the body that gives advice instead of decisions, the wording that must stay identical quietly paraphrased on run three. The handbook attacks each failure at the step where it is born — rule zero (produce the output by hand first, that artifact is the spec), trigger writing tested on paraphrases and near-misses, frozen blocks for anything that must not drift, and a failure table that only exists if the skill has actually been run.

Honest limitations

The method states which agents a skill was actually tested on and refuses to claim the rest. It will not make an untested workflow good — it shows you, quickly and on paper, that it isn't yet. Written from scratch from the author's own skill-production practice; it teaches a general workflow category and reproduces no third-party text.

Frequently asked questions

I already write prompts. What does this add?

A prompt is one run. A skill is every future run: triggering, gates for missing inputs, wording that must not drift, and tests. The handbook is about the parts a prompt never has to survive.

How do I know my skill is actually done?

Three unrehearsed test prompts — one casual, one underspecified, one at a sibling skill's boundary — scored on the included rubric. Ship at 10 of 12 with no zeros, or fix the earliest step that lost the points.

Does it work for non-Claude agents?

The method is agent-agnostic and the package format follows the open Agent Skills standard (SKILL.md plus folders). The honest rule stands: claim only the agents you tested on.
