What problem does it solve?

Ask a video model for a 60-second stickman video and you get the same four failures every time: the character is a different person in every scene, the story beats land in the wrong order, the narration runs long while the picture idles (or gets chopped to fit), and scene 4 has a caption typo nobody caught because nobody actually watched the assembled film. Generating scene-by-scene helps, but without a discipline around it you just get six unrelated clips with matching vibes.

How does it work?

1. Two engines, chosen up front — per-scene video-model generation for polished story films, or a local code renderer (frame-by-frame drawing + ffmpeg) for explainers and drafts at zero generation cost. Draft cheap on the code engine; spend credits only when the script has proven itself. 2. Five-beat script structure — hook, broken assumption, hidden mechanism, underlying truth, elevation; your source gets restructured for completion rate, not read aloud. 3. Frozen character and style blocks — written once, pasted verbatim into every scene prompt, with a reference-image workflow that uses the image for identity instead of accidentally turning it into scene 1. 4. Narration-led timing — voice first, picture cut to it, per-scene speed fitting, zero-gap joins, captions segmented by meaning and real speech pauses, plus a troubleshooting playbook for defective TTS renders. 5. An acceptance gate that watches the actual film — identity, beat order, contact, captions, sound and file, each recorded as pass / fail / not checked.

What is inside the package?

  • SKILL.md — the complete workflow: setup gate, five-beat scripting, storyboard contract, frozen-block character method for both engines, timing discipline, narration troubleshooting, code-synthesized music and loudness targets, assembly order, and the five-gate acceptance checklist
  • README.md — install instructions (one folder copy, zero dependencies) and what tools to bring for each engine
  • Works for explainers, story shorts, and narrated social video, in 16:9 or 9:16, in any narration language

Honest limitations

This is a workflow skill — prompts, structure, and checklists. It does not include a video model, a TTS service, or renderer software; you bring your own tools, and generation costs are whatever your provider charges. The character method reduces drift sharply; it does not guarantee zero retries on a video model. Anyone who promises that is selling you something else. The code-renderer engine trades visual richness for control and cost; it will not match a video model's motion, and the skill says so instead of pretending otherwise.

Frequently asked questions

Is this a video generator?

No. It is the production discipline — storyboard, character lock, timing, acceptance — that sits on top of whatever video and voice tools you already use.

Which engine should I start with?

The code renderer, because drafts cost nothing. Move to per-scene video-model generation once the script survives a cheap draft.

What do I need to run it?

Any agent runtime that supports SKILL.md skills, plus your own video/TTS tools for the engine you choose. The skill itself has zero dependencies.
