What problem does it solve?

It frames the question as a table before any searching: the columns every item must fill, the evidence each cell requires, and a hard line between "not found" and "does not exist". Work splits into independent units, parallel passes run on identical instructions and source standards, then a verification stage — spot-checks back to sources, a contradiction sweep, a not-found audit — decides what the synthesis may claim. Every finding ships labeled verified, single-source or inferred, and the gaps are reported as part of the result.

Who is it for?

Landscape surveys, vendor and tool comparisons, claim sweeps, literature scans — any job where the same questions must be answered about many things, by an agent setup that can run passes in parallel (or in disciplined sequence).

What do you get?

  • The six-step workflow as a SKILL.md: framing, unit splitting, parallel passes, cross-verification, synthesis, the one-page brief
  • A research schema template with column definitions, source standards and depth budgets
  • Verification rules: spot-check sampling, contradiction handling, confidence labels

Honest limitations

Parallel passes multiply throughput, not judgment — a bad schema gets forty bad cells instead of one, which is why framing is step one. Cross-verification catches inconsistency, not a source that is consistently wrong; for high-stakes claims, one human check against a primary source still beats any sweep, and the workflow says where. Frequently asked questions

Do I need multiple agents to use this?

Parallel agents make it fast, but the discipline — one schema, identical briefs, verification before synthesis — pays off even run sequentially, because the standards can no longer drift between items.

How is this different from just asking for a comparison?

Directly researched comparisons anchor on whichever item was read first. Here, comparisons are built at synthesis time from independently researched units, and every comparative claim names the cells it rests on.
